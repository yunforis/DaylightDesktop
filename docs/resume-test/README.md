生成日期：2026-10-15。共 **10 份 PDF、11 页**，包含 **8 份有文字层的 PDF + 2 份无文字层的扫描 PDF**。

所有候选人、联系方式、任职、成果、奖项和研究经历均为虚构测试资料；出现的真实学校名称仅用于测试字段提取，不代表真实就读经历。邮箱使用不可投递的 `example.invalid`，电话号码为 `000-0000-01xx` 占位值，网站为测试链接。**本套材料用于收信、附件解析与结构化提取；如后续测试邀约发信，先在待审核草稿中将收件人改为自己控制的真实测试邮箱。**

## 手动发送与核对

1. 使用 **HR 场景**账号，在「邮箱与模型设置」配置用于收信的邮箱与支持 JSON 输出的模型。
2. 建议一封邮件只附一份 PDF，共发送 10 封。主题使用 `【简历提取测试-01】陈知远-云平台后端工程师` 等格式，正文可统一写：

   ```text
   您好，附件是本次投递的求职简历，请查收。此邮件用于 Daylight 附件简历提取测试，所有简历资料均为虚构。
   ```

   正文无需重复候选人字段，便于单独检查 PDF 附件解析能力。只发送 PDF，**不要附上本说明或 expected-results.json**。
3. 将最近读取数量设为覆盖新邮件的范围（例如 20，最多 50）。在 Daylight 手动同步，或等待自动同步。
4. 在「智能招聘」查看人才库，并在「邮件助手」勾选「显示求职简历」，查看附件处理和日志。
5. 对照原 PDF 及 [expected-results.json](expected-results.json) 核对姓名、邮箱、电话、现居地、求职意向、学历、工作/实习、项目、技能、语言、证书等。JSON 中的 `sourceSections` 按原文保留经历与页码，`checks` 列出特殊检查点；它是人工核对基准，**不是预置模型响应，也不会被应用自动读取**。允许合理的同义归纳，不要求逐字相同；缺失字段允许为空或缺省。
6. 对照每段经历的 `evidence.page` 与 `evidence.quote`；特别确认 07 的第 2 页没有遗漏。字段不明确时应保留缺失，不根据毕业年份推算年龄，不把现居地当学校城市。
7. 在同一邮箱此前没有这些候选人的前提下，预期新增 **10 位候选人、10 份简历版本**，其中两位同名李沐独立建档。求职邮件不应新增日程或待办。06 可以缺联系方式入库。
8. 再次同步相同邮件，预期不重复创建候选人、不重复提取。09/10 首次 OCR 如需下载语言包，应有相应进度；网络或模型失败时查看错误并重试。

真实发送这些附件并通过 IMAP 收取，才是在真实邮件链路中验证；仅生成 PDF、检查文字层或使用本地解析不代表真实邮箱、模型结构化和 OCR 已成功。
