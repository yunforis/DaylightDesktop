# Daylight Desktop · 邮件日历桌面应用

一个基于 Tauri 2 的本地桌面邮箱 agent：展示日程，通过 IMAP 读取多个邮箱，调用大模型提取安排、邮件标签和待办，分别保存到本地。内置 Node.js 后台，无需用户安装 Node 或其他依赖。

项目保持 **React + Tauri 2 + 内置 Node 本地服务** 的规模；存储默认本地 JSON，可选 PostgreSQL / Redis / RabbitMQ。**暂不上 K8s**。

**当前功能：多个邮箱独立日历与待办、切换邮箱立即检查最近 N 封、已处理邮件不重复下载原文、冲突日程入历并标识、通过当前邮箱采纳并发送真实回信、3 个可行时段与待确认回复草稿，每分钟自动同步当前邮箱、邮件分类、摘要、优先级、日程新增/取消/调整、处理日志和草稿回放、智能招聘、PDF 简历 OCR、小 D 语音助手。**

- 操作和接入说明：本文件。
- 当前实现、代码入口及验证状态：[STATUS.md](STATUS.md)。
- 后续开发约定：[AGENTS.md](AGENTS.md)。

## 架构

```
Daylight Desktop（Tauri 2）
├─ React 前端（shadcn/ui + Tailwind + FullCalendar）
├─ Rust 壳层：窗口、托盘、单实例、系统凭据加密、外部链接
└─ 内置 Node 后台（runtime/）
   ├─ IMAP / SMTP / 大模型
   ├─ 日程 / 待办 / 招聘 / PDF / OCR
   └─ 本地数据存储
```

桌面端启动时自动创建本地用户（`owner@daylight.local`），无需注册登录。数据保存在系统应用数据目录。

| 搜索和筛选 | 搜索标题、地点、备注及来源邮件主题；按自定义日历分类筛选 |

| 模型提取 | 每封需提取的邮件调用一次模型，分类、摘要、日程与待办同次返回；单次请求最多等待 60 秒 |
| 日程冲突检测 | 非全天的新邀请或调整后的安排重叠时仍写入日历，并标识冲突；保留冲突详情、3 个候选时段和回复草稿；全天活动不占用冲突检测或候选时段 |
| 取消日程 | 识别取消通知，保留原安排并标记已取消；展示删除线、原因和变更邮件，不计入有效安排 |
| 调整日程 | 识别时间、地点等变化；取消原安排，按最新信息新建日程；未变化字段沿用原安排，可互相跳转；已是最新安排时不重复变更 |

| 来源追溯 | 在邮件助手中查看邮件正文及对应日程；日程保留邮件主题、发件人 |
| 邮件结构化展示 | 点击邮件记录，左侧查看原文、处理结果和关联日程，右侧查看邮件信息、内容摘要与提取的日程字段 |
| 邮件标签 | 每封新邮件选择 meeting/task/notice/inquiry/invoice/promo/resume 中一个分类；求职简历不创建日程或待办，邮件页可勾选是否显示 |
| 邮件待办 | 从需执行的事项提取任务、推断北京时间截止日期；日历旁展示待办，按优先级和截止时间排序，可完成或撤销 |
| 待办去重与来源 | 同一任务的提醒邮件合并到已有任务，保留各封来源邮件链接；点击查看原文与上下文 |
| 提取快照 | 新处理邮件保存新增/取消/调整字段；日程后续编辑或删除后，仍可查看当时提取的内容 |
| 去重和重试 | 先按 UID 去重，成功/跳过/冲突邮件不再下载原文；日程目标匹配失败且上下文未变时暂缓自动模型重试，手动同步可重试 |
| 处理日志 | 一封邮件一条 trace，记录分阶段输入、工具参数与返回摘要、输出、决策说明、耗时；失败与重试也保留 |
| 动态回放 | 日历和邮件助手均有日志面板；同步期间自动刷新，逐步播放、阶段折叠、时间轴与累计指标 |
| Token 和费用 | 读取接口实际 usage，按保存的人民币单价估算；真实邮件单独汇总总费用与单封平均分数 |
| 回复草稿与真实发送 | 根据已保存的处理结果生成草稿，无额外模型调用；真实邮件点击「采纳并发送」后，通过当前邮箱回信；可修改后发送、拒绝或在发送失败后重试，示例仅保存反馈 |
| 本地保存 | 保存日程、已处理邮件和连接配置；重启服务后保留 |
| 智能招聘 | `/app/recruitment`：PDF 简历 OCR 入库、自然语言筛选候选人、面试邀约审核后 SMTP 发送；可选飞书自动建会 |
| IMAP IDLE | 设置 → 同步策略可选 IDLE；有新邮件时推送同步，并保留慢轮询兜底 |
| 消息队列 | 默认启用 RabbitMQ；自动同步经 MQ 投递，连不上时回退进程内队列（设置页展示 `mq` 真实状态） |

当前 agent 每分钟自动执行，也可手动触发：**检查当前邮箱最近邮件的 UID → 读取未处理邮件原文 → 按时间从早到晚处理 → 同次模型请求提取标签、摘要、日程和待办 → 保存日程并检测、标识冲突 → 生成回复草稿 → 用户采纳后通过当前邮箱发送回信**。新增/切换邮箱会立即检查该邮箱设定数量的邮件；已处理邮件继续去重。自动同步只生成草稿，真实发送由用户点击触发。时间统一展示为北京时间。

**示例新增、取消与调整已本地验证；真实 QQ 邮箱 + DeepSeek 的邀请提取此前已验证。** 本地测试与用户真实联调分别记录在 `STATUS.md`。

## 2. 启动项目

### 桌面端开发启动

默认使用 **Node.js 22**（仓库含 `.nvmrc`，本地用 `nvm use` 即可）。Rust 工具链已内置在 `work/toolchain/`，无需单独安装。

```bash
cd DaylightDesktop
nvm use
npm install
npm run desktop:dev
```

这会启动 Tauri 桌面窗口 + 前端热更新 + Node 后台。窗口打开后直接进入工作区，无需登录。

首次运行会自动准备内置 Node 运行时（`src-tauri/runtime/`），后续启动更快。

### 仅前端开发（浏览器调试）

```bash
npm run dev
```

浏览器打开 **http://127.0.0.1:3000**，会自动重定向到 `/app` 工作区。前端和 API 由同一个本地进程提供。按 `Ctrl+C` 停止。

### 打包桌面安装包

```bash
npm run desktop:build
```

产物在 `src-tauri/target/release/bundle/`：
- macOS：`macos/Daylight.app`（可直接双击运行）
- macOS dmg：`dmg/Daylight_0.1.0_aarch64.dmg`（安装包）
- Windows / Linux：在对应平台运行相同命令

### 端口冲突

```bash
PORT=3001 npm run dev          # macOS/Linux
$env:PORT='3001'; npm run dev  # PowerShell
```

后端代码更新后需重启服务；前端 Vite 热更新无需重启。

## 3. 演示日程、冲突与待办（无需邮箱和 Key）

### 演示日程冲突和回复确认

1. 在日历右侧或「邮件助手」点击「演示日程冲突」。这个演示可独立使用，会读取 2 封**预置提取结果**，不连接真实邮箱、不调用模型。
2. 两封邀请都加入日历：明天 09:00–10:00 的「项目进度沟通」和 09:30–10:30 的「新功能讨论」。两项重叠的有效安排显示「时间冲突」标识。
3. 日历和邮件助手显示「日程冲突」卡片。点击后，在邮件详情查看已加入的安排、冲突日程的名称/时间/地点，以及 3 个建议时段。也可以从日程详情查看重叠安排和来源邮件。
4. 点击「查看并确认回复草稿」，查看已自动写好的回复：说明邀请与「项目进度沟通」冲突，列出各自时间，并提供 3 个可行替代时段。可以采纳、修改后保存或拒绝；刷新后仍保留反馈。
5. **预置示例的草稿操作只保存反馈，不会发送邮件，也不会把建议时段直接写入日历**。真实邮件的发送方式见第 4 节。达成安排后可手动新建日程，或同步发件人的新邀请/改期邮件。
6. 再次点击演示会按邮件 ID 跳过。要从头演示，可在设置清除示例数据后重来；这会保留手动和真实邮件数据。

冲突按实际时间重叠判断，前项结束与后项开始相同不算冲突；已取消日程不占时间，旧数据没有 `status` 仍有效。**标记为全天（`allDay: true`）的活动不参与冲突检测：无论当天已有安排，都正常加入日历，也不阻挡其他活动或候选时段。** 跨多天的全天活动同样适用；未标记全天的跨天安排仍检测重叠。真实邮件比较有效的真实/手动日程，预置演示只比较示例日程。手动新建/编辑沿用原操作入口。

候选时段按北京时间从原请求时间与处理时刻中的较晚者开始寻找，保留原时长：普通活动在每天 **09:00–18:00**、半小时刻度推荐 3 个互不重叠的空档，包含周末；超过 9 小时的非全天长活动保留原开始钟点和实际时长逐日寻找。全天活动不占用候选时段。根据已保存的日历继续向后找，不因前几天忙满而编造空档。这些候选只代表处理时自己的日历空闲，不代表对方可用或已预订。

有冲突的调整同样取消旧安排、新建最新安排并标识冲突；原/新日程关联保留。同封邮件的其他日程及待办正常保存。冲突邮件已完成分析并保存草稿，再同步会去重，不反复调用模型。日历标识按当前有效安排展示；历史冲突对象、草稿与候选是处理时快照，之后日历变化不会自动重算旧建议或自动重新导入。此前版本暂缓入历的冲突记录保留原样，新行为适用于新处理的邮件。

### 演示新增、取消与调整

1. 如需从头演示，在「邮箱与模型设置」点击「清除示例数据」。这会清除示例日程和示例邮件，保留手动日程、真实邮件日程及连接配置。
2. 在日历点击「导入示例邮件」，或进入「邮件助手」点击「体验示例导入」。首次生成设计评审、咖啡见面、工作坊 3 项日程，另 1 封资讯跳过。
3. 先在日历查看原安排：设计评审在明天 14:00–15:30、腾讯会议；咖啡见面在 3 天后 16:00–17:00、好天气咖啡。
4. 进入「邮件助手」，点击「演示取消与调整」。会导入 2 封通知：咖啡见面取消，设计评审改到后天 10:00–11:30、创意园 A 栋 302。
5. 回到日历：咖啡原安排显示「已取消」和删除线；评审原安排显示「已调整」和删除线，新时间出现「调整后」日程。工作坊保持有效。原安排留在日历用于追溯，不计入有效安排数。
6. 打开原日程查看取消/调整原因、变更邮件和更新时间；打开评审后点击「查看调整后的日程」。新日程也可返回原日程。
7. 在邮件助手打开两封通知，查看原文、处理结果和相关原/新日程。再次点击演示按钮，两封已处理通知会跳过，避免重复变更。

两步示例都使用预置提取结果，**不连接真实邮箱、不调用真实模型**。日期以导入当天为基准，邮件 ID 固定；示例变更只会匹配示例日程。若删除了相关示例日程，清除示例后重新导入即可。

### 演示邮件标签和待办

1. 在日历的「待办」栏或邮件助手点击「演示标签与待办」，导入 6 封预置邮件。无需填写邮箱和模型配置。
2. 查看 3 条待办：提交 Daylight 项目报告、回复确认演示方案、提交工作坊报销申请。报告和提醒是同一任务，列表只建一条，并保留两封来源邮件。
3. 「本周五前」按邮件日期所在周推断为周五 18:00；「下周一前」为下周一 18:00；明天中午回复保留明确的 12:00。日期事项默认 18:00，未说明截止日则显示未注明，不凭空添加日期。
4. 查看邮件记录和邮件详情里的分类、优先级和摘要。分类只选一个：`meeting`（会议邀请/改期）、`task`（派活）、`notice`（通知公告）、`inquiry`（需要回复的问题）、`invoice`（发票/报销）、`promo`（推广/垃圾）。日程邀请示例可查看 meeting 标签。
5. 优先级按处理时的北京时间判断：今天或明天需要行动为 `high`；仅需知晓为 `low`；其余为 `normal`。待办按 high、normal、low，再按截止时间排列；过期任务另有逾期提示。
6. 勾选任务标记完成；在「已完成」里可撤销。刷新页面仍保留状态。点击任务中的来源邮件链接，会打开原邮件详情；链接 `/?mailbox=<邮箱ID>&email=<邮件ID>` 会切换到对应邮箱并定位本地已保存的上下文，旧 `/?email=<邮件ID>` 链接仍可定位当前邮箱的邮件。
7. 再次导入同组示例，按邮件 ID 跳过。清除示例数据会一并清除示例待办、邮件和日志，保留真实邮件待办、手动日程和配置。

这组标签、摘要和任务使用**预置结果**，不代表真实模型的分类或日期识别效果。真实同步在每封邮件原有的一次模型请求中完成全部提取。模型会结合已保存任务匹配重复事项，应用同时按规范化任务名称和截止时间合并相同任务；提醒邮件不会重新打开已完成任务。复杂语义的合并仍取决于模型。

历史已处理邮件不自动补标签或待办，不额外调用模型。已有成功/跳过记录仍会去重；要验证真实新字段，请同步一封新的测试邮件。

日程取消/调整使用前面的两步示例，标签与待办使用独立演示；真实模型的识别效果可按第 5 节复验。

### 查看邮件原文与结构化字段

1. 在左侧导航点击「邮件助手」，找到「邮件处理记录」。
2. 点击任意一封邮件，打开「邮件详情」。宽屏左侧保留邮件原文、处理结果和新增/取消/调整的关联日程；右侧展示「邮件结构化字段」。窄屏上下排列，向下滚动即可查看字段。
3. 右侧包括主题、发件人、邮件时间、来源、处理时间、内容摘要、日程操作，以及每项日程的名称、起止时间、是否全天、所属日历、地点和关键事项。取消和调整还显示原因及关联原日程；调整展示继承未变化字段后的新安排。
4. 点击「查看日程」可以打开关联日程详情。新处理邮件会保存独立提取快照，后续修改或删除日程不会改变当时提取的字段。无日程邮件也会保存模型摘要，并显示「无日程操作」。

示例中的摘要与日程字段均为**预置结果**。真实邮件在原有的一次模型请求中同时提取摘要和日程，无额外模型调用。

历史邮件没有提取快照时，右侧使用现有邮件信息和当前关联日程字段，并明确提示来源；不补写摘要、不重新调用模型。已成功处理或跳过的邮件仍遵守去重规则。要体验完整新字段，可导入尚未处理的示例或同步一封新邮件。

### 查看处理日志、回放和回复草稿

1. 在「我的日历」下方或「邮件助手」中找到「处理日志」面板。自动或手动同步时，日志与日历会自动刷新；处理完一封邮件，日程就会写入并显示，无需等整批结束。模型请求期间可看到当前运行的阶段。
2. 选择一封邮件，查看本次及历史重试的时间轴。每个阶段可展开查看决策摘要（Thought）、工具动作（Action）、返回结果（Observation）、脱敏输入和输出快照。这里的 Thought 是应用的简短决策说明，不记录模型私有推理。只展示实际执行的步骤。
3. 点击回放，用播放或逐步前进查看「收信 → 解析 → 查询当前日历 → 模型提取 → 检测冲突并保存 → 生成草稿」。回放读取保存的证据，不重新调用模型，也不重复修改日历。邮件详情中的回放入口会定位对应日志。
4. 在草稿区域查看回复。草稿按新增、取消、调整、冲突或无日程结果在本地生成，发送前标明未发送。冲突草稿说明已有安排并提供 3 个候选；真实邮件可点击「采纳并发送」，编辑时先保存修改稿，再采纳发送；拒绝只保存反馈。示例采纳仍只保存反馈。发送成功会展示时间并禁用编辑和再次发送；发送失败保留草稿供重试。草稿操作不撤销已同步的日程，也不创建候选日程。
5. 失败日志显示出错步骤与错误摘要；再同步成功后，同一封邮件仍是一条 trace，各次尝试分别保留。失败请求已经返回的 Token 和费用也计入这封邮件的累计值。重复同步已处理邮件不再创建尝试、不再计费。「待匹配原日程」表示仍未处理成功；上下文未变时，自动同步不新增模型调用或日志尝试。补充或修正原日程后会恢复自动重试，也可点击「同步真实邮箱」手动重试。

日志只保存短快照：邮箱地址、手机号、已配置密钥、常见密钥格式和链接中的凭据/查询参数会脱敏；长文本和长数组会截断。邮件 ID 使用摘要关联，原文仍在原有邮件详情中查看。历史邮件在本功能上线前没有执行日志，页面会提示缺少记录；不会补造工具调用、耗时或 Token，也不会为了补日志重新处理邮件。

示例使用同一日志面板演示流程，明确标注「预置结果」，模型 Token/成本为零。示例不会进入真实邮件平均费用。

### 配置费用统计

在「邮箱与模型设置」填写输入、输出和缓存输入的 **人民币单价（元 / 百万 Token）**，数值以所用模型服务商的计价页面为准。单价允许为 0；留空表示尚未配置。按实际返回的缓存命中数量分开计算：

```text
估算费用（元） = ((输入 Token − 缓存命中 Token) × 输入单价
               + 缓存命中 Token × 缓存输入单价
               + 输出 Token × 输出单价) / 1,000,000
单封平均（分） = 真实邮件累计费用 / 真实邮件数 × 100
```

一封邮件重试多次的成本会累加，邮件数仍只算一封。模型用量支持 Chat Completions 的 `usage.prompt_tokens` / `completion_tokens`，缓存命中支持 `prompt_tokens_details.cached_tokens` 或 `prompt_cache_hit_tokens`。模型费用是按本次保存单价计算的估算，不是服务商账单；修改单价不追溯改写已有调用。

如果接口没返回 usage，或有计费 Token 对应的单价未填，费用显示「未知」。汇总同时展示已知费用及覆盖数量；完整平均费用只有全部真实邮件费用已知时显示，已知样本的平均值单独标注。不会把未知费用当作零。无需缓存输入价格的请求（缓存命中为 0）只要求输入和输出价格。

## 4. 接入多个邮箱

### 开启邮箱的 IMAP/SMTP 客户端服务

在邮箱服务商的设置中启用 IMAP/SMTP，取得第三方客户端使用的授权码、应用专用密码或被允许的客户端密码。QQ 默认选项继续可用，可在 [QQ 邮箱](https://mail.qq.com/) 设置中开启服务并生成授权码；163、126、Gmail、Outlook 和 iCloud 按各自账号的服务要求设置。

当前使用邮箱地址 + 客户端凭据登录标准 IMAP/SMTP，不提供 OAuth 登录。服务商或组织若只允许 OAuth，不能仅凭服务器预设完成连接；需要使用允许这种客户端登录方式的邮箱。

### 在 Daylight 新增、设置和切换邮箱

1. 打开「邮箱与模型设置」，选择已有邮箱进行编辑，或点击新增邮箱。
2. 选择邮箱服务，填写地址、客户端授权码/密码以及每次读取数量。首次联调建议先设为 3–5 封。
3. 预设会填写服务器；企业邮箱或其他邮箱选择「自定义」，在服务器设置中填写 IMAP、SMTP 主机、端口和连接方式。
4. 保存新邮箱后，页面切换到它自己的日历、待办和邮件记录。邮箱和共用模型配置完整时，新增/切换会立即在后台同步最近 N 封；处理期间可查看日志。
5. 使用侧栏的当前邮箱选择框切换，或在设置中选择已保存邮箱。切回旧邮箱会恢复它原有的日程、待办完成状态、草稿和日志，同时重新读取该邮箱最近 N 封；已经成功处理或跳过的邮件不会再次调用模型，失败邮件可以重试。

| 邮箱服务 | IMAP | SMTP |
| --- | --- | --- |
| QQ 邮箱（默认） | `imap.qq.com:993`，直接 TLS | `smtp.qq.com:465`，直接 TLS |
| 163 邮箱 | `imap.163.com:993`，直接 TLS | `smtp.163.com:465`，直接 TLS |
| 126 邮箱 | `imap.126.com:993`，直接 TLS | `smtp.126.com:465`，直接 TLS |
| Gmail | `imap.gmail.com:993`，直接 TLS | `smtp.gmail.com:465`，直接 TLS |
| Outlook | `outlook.office365.com:993`，直接 TLS | `smtp-mail.outlook.com:587`，STARTTLS |
| iCloud | `imap.mail.me.com:993`，直接 TLS | `smtp.mail.me.com:587`，STARTTLS |
| 自定义 IMAP/SMTP | 手动填写 | 手动填写 |

每个邮箱分别保存邮箱服务、地址、客户端凭据、服务器和读取数量（1–50 封，默认 15 封）。收信和发信共用该邮箱的客户端凭据。直接 TLS 选项关闭时使用 STARTTLS，仍要求加密连接。SMTP 使用操作系统 DNS 解析主机，并按配置的 SMTP 域名验证 TLS 证书，不固定 IP。读取范围是 `INBOX` 最近 N 封，包含已读和未读邮件。

日程、待办、邮件、冲突、草稿、日志和费用按邮箱独立保存，取消/调整匹配和任务去重仅查看当前邮箱。模型 URL、API Key、模型名称及 Token 单价共用。换成新的邮箱地址会创建或切换到独立邮箱，不继承其他地址的授权码或日历。同步或发信期间暂停邮箱切换，完成后再切换。

服务每分钟只自动同步当前邮箱；也可以点击日历或邮件助手的「同步真实邮箱」。**保存配置或显示“已配置”只表示字段已保存，不表示连接成功。** 首次填写原默认邮箱后，可立即手动同步或等待下个自动周期；发信连接发生在点击「采纳并发送」时。发送已有草稿不需要模型配置。编辑同一邮箱时，凭据留空保留该邮箱已保存的值；新增地址需要自己的凭据。

### 采纳草稿并发送真实回信

更新代码后，重启正在运行的本地 Node 服务（开发模式重新执行 `npm run dev`），再刷新页面使用发送入口。

1. 打开一封已同步的真实邮件，在处理日志中查看回复草稿。旧版本已点击「采纳草稿」的记录也可发送：此前的采纳只记录了反馈，尚未发信。
2. 核对草稿；需要修改时点击编辑，先保存修改稿。编辑器展示准备发送的正文，普通联系方式和链接查询参数按原文保留；发送时优先使用已保存的修改稿，没有修改稿则使用原稿。旧版本的修改稿若已被脱敏，无法恢复其中的内容，可重新编辑补全后发送。
3. 点击「采纳并发送」，服务使用当前邮箱的 SMTP 配置回信给原邮件 `Reply-To` 中的第一个有效邮箱地址；没有有效 `Reply-To` 地址时回复发件人。页面提示仅回复这个地址，不执行「回复全部」。主题使用 `Re:`，新读取邮件保留原邮件的 `Message-ID` 和 `References`，用于设置回复关联；历史邮件没有这些头信息时仍可按已保存的发件人地址回信。其他邮箱的草稿在当前空间不可见，也不能在此发送。
4. 成功后查看发送时间，刷新仍保留发送状态，编辑和发送按钮禁用。相同草稿的成功记录不会再次发送。失败会显示错误并保留草稿；检查 IMAP/SMTP 服务和授权码后可再次点击重试。
5. 在发件人的邮箱确认收到回信。页面「已发送」表示配置的 SMTP 服务已接受邮件，不等于收件人最终收到或已读。本 demo 没有额外向「已发送」文件夹归档的操作。

拒绝草稿不会发信；预置示例仍只保存采纳、修改或拒绝反馈。自动同步不会自动发信，发送回信也不会把冲突候选时段加入日历。

### 每分钟自动同步

- 启动 `npm run dev` 或 `npm start` 后，Node 服务每 60 秒检查当前邮箱和共用模型配置；配置完整时同步当前邮箱，其他邮箱在切换后同步。
- 自动同步先获取最近 N 封的 UID 和日期，按当前邮箱的邮件 ID 去重；成功、跳过或已有冲突草稿的邮件不重复下载原文，也不调用模型。未处理邮件读取原文后按时间顺序解析，日程和待办直接导入，冲突日程同时标识并生成待确认回复草稿。
- 日程取消/调整因目标缺失、不唯一或无效而失败时，若当前有效日程、已有任务和模型接口/名称/提取规则版本未变，自动同步及邮箱切换同步会暂缓该邮件的模型重试。错误仍保留，不标为成功；补充或修正日程、改变任务或模型上下文后会恢复，手动同步也可立即重试。暂缓的失败邮件仍会读取原文。网络、服务商、响应格式和其他处理错误继续在后续周期重试，均受最近 N 封范围限制。
- 自动同步和手动同步共用一次处理流程；已有同步正在运行时，本轮自动同步跳过，避免同时处理。页面会定期刷新状态，自动同步有新处理结果或新失败时显示提示；仅有已暂缓的匹配错误时不反复弹出提示。
- 关闭页面后，只要 Node 服务仍运行，自动同步继续；停止服务后自动同步也停止。这里使用每分钟轮询，不是收件推送。

## 5. 配置真实模型 API

本项目使用 **OpenAI 兼容 Chat Completions 接口**。所选模型需支持 `messages`、`system` 提示词，以及 `response_format: { "type": "json_object" }`。

在同一个设置窗口填写：

| 页面字段 | 填写内容 |
| --- | --- |
| Base URL | 模型服务商给出的兼容接口基础地址 |
| API Key | 该服务商的 API 密钥 |
| 模型名称 | 该服务商提供的准确模型 ID，且你的账户有调用权限 |

本机已成功使用的 DeepSeek 配置如下（不含 API Key）：

```text
Base URL: https://api.deepseek.com
模型名称: deepseek-flash
实际请求: POST https://api.deepseek.com/chat/completions
```

这组配置已由用户通过真实邮件联调确认。程序初始默认的 `https://api.deepseek.com/v1` / `deepseek-chat` 是另一组填写示例，当前本机已改用上述配置。

连接官方 `api.deepseek.com` 且模型为 `deepseek-flash` 或 `deepseek-v4-pro` 时，提取请求明确关闭思考模式，减少本任务不需要的推理等待。其他模型或兼容服务按通用 Chat Completions 格式请求。每次模型请求设 **60 秒等待上限**，覆盖请求与响应正文读取；超时后保留失败记录，其他邮件继续处理。该上限针对单次模型调用，整批同步仍包含邮箱连接、邮件读取及各封模型请求的耗时。

其他填写示例如下；具体模型可用性和权限以服务商控制台为准。通义千问、OpenAI 及表中其他模型组合尚未在本项目中实连验证。

| 服务商 | Base URL | 模型名称示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| OpenAI | `https://api.openai.com/v1` | 账户可用、支持 Chat Completions 和 JSON object 输出的模型 ID |

例如选择 DeepSeek，可填写第一行的 URL、你的 DeepSeek API Key 和 `deepseek-chat`，再点击「保存配置」。初始 URL 和模型名称只是默认值，仍需要填写真实 Key。

后端会在 Base URL 后追加 `/chat/completions`；如果填写的地址已经以 `/chat/completions` 结尾，会直接使用该地址。例如：

```text
Base URL: https://api.deepseek.com/v1
实际请求: POST https://api.deepseek.com/v1/chat/completions
鉴权: Authorization: Bearer <你保存的 API Key>
```

请求包含邮件日期、当前北京时间、主题、发件人、正文，以及当前邮箱有效的非示例日程和已有非示例任务摘要，用于匹配取消/调整对象和重复任务。其他邮箱的日程、任务和邮件不会进入这次模型请求。模型在同次请求中返回 `summary`、`category`、`priority`、`events`、`tasks`。共用模型配置保存在 `data/settings.json`；无需创建 `.env`。

### 真实流程复验或首次配置新环境

当前本机已完成真实联调。更换环境、模型或验证新功能时，可以按以下步骤复验：

1. 保存邮箱地址、授权码、Base URL、API Key 和模型名称，将读取数量设为 3–5 封。
2. 向当前邮箱发送一封新的测试邮件，写清具体日期、时间和地点，例如：

   ```text
   主题：Daylight 日程提取测试
   正文：邀请你参加产品评审，时间为 2026 年 10 月 20 日 14:00–15:00，
   北京时间，地点为腾讯会议 123 456 789。请带上最新设计稿。
   ```

   将示例日期改为你准备测试的日期，并确保测试邮件位于收件箱最近 N 封范围内。

3. 等待下一个每分钟自动同步周期，或点击日历/邮件助手「同步真实邮箱」。有明确的安排会自动生成日程，有冲突也会入历并标识，可查看冲突详情和待确认回复草稿。
4. 查看日历中的日程和邮件助手中的来源记录；核对时间、地点和标题。
5. 再次同步，同一封已处理邮件应跳过。

### 真实邮件演示取消与调整

先把读取数量设为能覆盖测试邮件的范围，例如最近 10 封。建议用同一发件人，保留独特活动名及原时间地点；可以回复原邀请发送通知。以下均为专门编写的测试文案，时间为北京时间，按演示当天修改日期。

**取消流程：**

1. 发送主题「Daylight 演示 A：产品评审邀请」，正文「邀请你参加 Daylight 演示 A 产品评审，2026 年 10 月 20 日 14:00–15:00，地点会议室 A。」
2. 点击「同步真实邮箱」，确认邀请已生成日程。
3. 再发送主题「取消：Daylight 演示 A 产品评审」，正文「原定 2026 年 10 月 20 日 14:00–15:00 在会议室 A 的 Daylight 演示 A 产品评审取消。原因：负责人临时出差，无需参加。」
4. 再次同步，确认原日程有「已取消」提示；在详情里查看原因及变更邮件。

**调整流程：**

1. 发送主题「Daylight 演示 B：设计沟通邀请」，正文「邀请你参加 Daylight 演示 B 设计沟通，2026 年 10 月 21 日 10:00–11:00，地点会议室 B。请携带设计稿。」同步确认日程已生成。
2. 再发送主题「调整：Daylight 演示 B 设计沟通」，正文「原定 2026 年 10 月 21 日 10:00–11:00 在会议室 B 的 Daylight 演示 B 设计沟通调整为 2026 年 10 月 22 日 15:00–16:00，地点改为会议室 C。原时间的安排取消，其他事项不变，请以最新通知为准。」
3. 同步后确认原时间保留「已调整」记录，10 月 22 日新建有效日程，时间和地点正确；打开原/新日程互相跳转。
4. 重复同步确认没有重复新增、取消或调整。也可在调整后再发送新的取消通知，明确指向调整后的时间地点，验证最新安排取消。

同一批同时包含邀请和变更时，会按邮件时间从早到晚处理。模型从当前有效的真实/手动日程中选择唯一目标，按正常取消或调整流程更新。当前提取规则还包括：

- 通知对应的活动已能唯一确认，且时间、地点及其他变更都与日历中的最新安排一致时，不重复调整或创建，保留说明摘要。
- 没有任何相关原安排或最新安排，但调整通知给出了明确日期及完整可参加的新活动时，可按通知直接创建最新安排，并在备注说明来源。
- 没有相关日程的纯取消通知保留摘要，不修改其他安排。
- 有疑似目标但不能唯一匹配，或调整内容不足以形成完整安排时仍显示失败，不猜目标、不部分写入。上下文未变时暂缓自动模型重试，手动同步可以重试；返回无效目标或无效时间也会失败。暂无人工选择候选界面，可补建或修正原日程，或发送说明更明确的新通知。

此前多邮箱与冲突入历使用合成数据验证；本次同步优化另有真实 IMAP 和官方 DeepSeek 复验，见 `STATUS.md`。上述步骤用于逐项复验新功能，内置预置演示不代表真实模型识别结果。

### 真实邮件复验冲突

1. 先选一个测试日期，手动新建「冲突测试·已有安排」，例如 2026 年 10 月 23 日 14:00–15:00。
2. 发一封新的测试邮件到当前邮箱：主题「冲突测试·讨论邀请」，正文「邀请你参加冲突测试讨论，2026 年 10 月 23 日 14:30–15:30，地点会议室 C。如果时间不方便，请提供其他时段。」按演示当天修改日期，并确保邮件位于最近 N 封范围内。
3. 手动同步或等待自动同步。核对原日程保留、新邀请已加入，两个安排显示冲突；打开冲突卡片核对标题和时间，查看含 3 个可行时段的待确认回复草稿。改期冲突同样入历，原安排标记已调整。
4. 核对回复内容，可修改后保存，再点击「采纳并发送」；在测试发件人邮箱确认收到回信。刷新后应保留发送时间，无法再次发送；拒绝则只保存反馈。再次同步应跳过原邮件，发送回信不会创建建议日程。
5. 另发一封日期/时间与有效日程完全错开的新邀请，确认它可以正常自动创建。

冲突判断和候选生成在本地执行，复用模型提取的时间字段，不增加模型调用。多邮箱切换、冲突入历与草稿发送已有本地合成数据验证；新流程及其他邮箱仍需真实服务复验，历史 QQ SMTP 连接和完整回信送达记录见 `STATUS.md`。

### 当前错误提示怎么处理

- **邮箱登录失败**：检查邮箱地址、IMAP 是否开启，以及授权码是否有效。
- **回信发送失败**：检查当前邮箱 SMTP 服务是否开启、服务器/端口/连接方式、邮箱地址和客户端凭据是否正确，以及网络连接；草稿保留，可检查后重试。
- **DNS lookup for smtp.qq.com timed out**：本次已改为使用系统 DNS，修复本机 Nodemailer 直接 DNS 查询超时的问题；重启 Node 服务后再发送。如果系统 DNS 本身也无法解析，检查本机网络或代理的 DNS 设置。
- **模型提示 Key、权限或额度错误**：检查 API Key、模型名称及服务商账户状态。
- **模型返回格式或日期错误**：确认模型支持上述 Chat Completions 和 JSON object 请求格式；当前代码会提示格式错误。
- **模型请求超过 60 秒**：本次已停止等待并保留失败；检查服务商状态和网络后可再次同步，后续自动周期也会重试。
- **取消/调整匹配失败或待匹配原日程**：核对原日程是否存在且有效，通知中补充独特活动名和原时间地点；手动日程可被真实邮件匹配，示例日程不会被真实邮件改变。匹配上下文未变时自动同步暂缓重复模型请求；补充/修正原日程后会恢复，也可手动点击「同步真实邮箱」重试。
- **显示日程冲突**：冲突安排已写入并标识；打开冲突卡片核对安排和 3 个建议时段，再采纳、修改或拒绝回复草稿。建议时段不会自动替换日历，新的明确改期通知可更新日历。此前版本暂缓的历史记录仍保留原样。
- **没有日程变更**：查看该邮件是否已处理、是否有冲突提示、是否包含明确安排，或是否已超出最近 N 封读取范围。

单封提取失败不会阻止其他邮件继续处理。失败邮件不写入已处理记录，仍处于读取范围内时可手动重试；目标匹配失败按上面的上下文规则恢复自动重试，其他故障在后续自动周期继续重试。

已成功处理、跳过或保存冲突草稿的邮件会被记住。更换模型或删除对应日程后，同一封邮件也不会重新提取；再次联调可发送一封新的测试邮件。

## 6. 本地数据和当前边界

- `data/calendar.json`：日程、待办及完成状态、已处理邮件正文与标签、来源关联、邮件结构化提取快照、冲突对象与候选时段、邮件 `draftReply` 原始草稿及 `userDraft` 修改稿原文、最近同步时间。页面编辑器和真实发送使用这里保存的完整正文。
- `data/settings.json`：邮箱列表、当前邮箱 ID、各邮箱地址、客户端凭据、IMAP/SMTP 服务器及读取数量，以及共用模型 API Key、URL、模型名称和单价。
- `data/traces.json`：脱敏处理日志、阶段快照、工具调用摘要、用量与计价快照、累计费用、各次重试、脱敏草稿证据、用户反馈及 `reply_delivery` 发送状态（成功时间/邮件 ID 或失败时间/脱敏错误）。日志草稿证据与准备发送的正文分别保存。
- 原默认邮箱继续使用 `data/calendar.json` 和 `data/traces.json`；新增邮箱分别使用 `data/mailboxes/<邮箱 ID>/calendar.json` 和 `traces.json`。首次读取旧设置时兼容原邮箱，已有数据不会被清空或搬走；新增邮箱从空日历和待办开始，示例可在该空间单独导入或清除。

上述 JSON 文件以明文保存在本机；页面 API 不回传已保存的密钥值。真实同步时，未处理邮件、当前有效日程和已有任务摘要会发送到你配置的模型服务商。`data/` 已加入 `.gitignore`，分享源码时请排除该目录。

当前服务每分钟自动同步，也支持手动点击同步，识别正文中的新邀请、取消和时间/地点等调整。自动同步只在本地 Node 服务运行且邮箱、模型配置完整时执行，读取范围仍是最近 N 封。原取消日程保留用于展示和追溯；调整后的日程独立保存，未提及的字段继承原安排。旧数据没有 `status` 字段时作为有效安排处理，无需迁移或重新配置。

每次同步仍需连接 IMAP、打开 INBOX 和检查元数据；首次全新邮件仍需读取原文并按时间逐封调用模型。未处理邮件仍下载整封源数据，包括附件字节，但只分析正文，没有附件解析能力。暂停模型重试的匹配失败邮件也仍读取原文；免下载原文适用于已成功处理、跳过或保存冲突草稿的邮件，不保证所有同步零下载或固定耗时。

目标匹配依赖配置的模型；名称相近、通知信息不完整时，识别效果需要真实邮件验证。待办支持在当前邮箱内跨邮件合并；普通新邀请按不同邮件分析，不做活动层面的自动合并。非全天邀请重叠也加入日历，保留冲突标识和回复流程，全天活动正常加入且不占时段。已取消活动重新邀请应作为新日程。待办来源链接指向本地保存的邮件详情。真实回信使用当前邮箱的已保存草稿与 SMTP 配置；附件识别、OAuth、提醒、实时收件监听和第三方日历同步尚未实现。其他邮箱服务的实际可用性仍需按账号权限实连验证。

模型提示词要求明确日期、相对日期参考邮件日期、缺少结束时间默认一小时、日期事项生成全天日程。真实测试邮件已成功生成日程；复杂日期、多日程及其他邮件格式的提取效果仍需按后续需求验证。

冲突按实际时间重叠判断，前项结束与后项开始相同不算冲突；已取消日程不占时间，旧数据没有 `status` 仍有效。**标记为全天（`allDay: true`）的活动不参与冲突检测：无论当天已有安排，都正常加入日历，也不阻挡其他活动或候选时段。** 跨多天的全天活动同样适用；未标记全天的跨天安排仍检测重叠。真实邮件比较有效的真实/手动日程，预置演示只比较示例日程。手动新建/编辑沿用原操作入口。

候选时段按北京时间从原请求时间与处理时刻中的较晚者开始寻找，保留原时长：普通活动在每天 **09:00–18:00**、半小时刻度推荐 3 个互不重叠的空档，包含周末；超过 9 小时的非全天长活动保留原开始钟点和实际时长逐日寻找。全天活动不占用候选时段。根据已保存的日历继续向后找，不因前几天忙满而编造空档。这些候选只代表处理时自己的日历空闲，不代表对方可用或已预订。

有冲突的调整同样取消旧安排、新建最新安排并标识冲突；原/新日程关联保留。同封邮件的其他日程及待办正常保存。冲突邮件已完成分析并保存草稿，再同步会去重，不反复调用模型。日历标识按当前有效安排展示；历史冲突对象、草稿与候选是处理时快照，之后日历变化不会自动重算旧建议或自动重新导入。此前版本暂缓入历的冲突记录保留原样，新行为适用于新处理的邮件。

日程取消/调整使用前面的两步示例，标签与待办使用独立演示；真实模型的识别效果可按第 5 节复验。

### 查看邮件原文与结构化字段

示例中的摘要与日程字段均为**预置结果**。普通正文邮件在原有的一次模型请求中同时提取摘要和日程，无额外模型调用。

历史邮件没有提取快照时，右侧使用现有邮件信息和当前关联日程字段，并明确提示来源；不补写摘要、不重新调用模型。已成功处理或跳过的邮件仍遵守去重规则。要体验完整新字段，可导入尚未处理的示例或同步一封新邮件。

### 查看处理日志、回放和回复草稿

1. 在「我的日历」下方或「邮件助手」中找到「处理日志」面板。自动或手动同步时，日志与日历会自动刷新；处理完一封邮件，日程就会写入并显示，无需等整批结束。模型请求期间可看到当前运行的阶段。
2. 选择一封邮件，查看本次及历史重试的时间轴。每个阶段可展开查看决策摘要（Thought）、工具动作（Action）、返回结果（Observation）、脱敏输入和输出快照。这里的 Thought 是应用的简短决策说明，不记录模型私有推理。只展示实际执行的步骤。
3. 点击回放，用播放或逐步前进查看「收信 → 解析 → 查询当前日历 → 模型提取 → 检测冲突并保存 → 生成草稿」。回放读取保存的证据，不重新调用模型，也不重复修改日历。邮件详情中的回放入口会定位对应日志。
4. 在草稿区域查看回复。草稿按新增、取消、调整、冲突或无日程结果在本地生成，发送前标明未发送。冲突草稿说明已有安排并提供 3 个候选；真实邮件可点击「采纳并发送」，编辑时先保存修改稿，再采纳发送；拒绝只保存反馈。示例采纳仍只保存反馈。发送成功会展示时间并禁用编辑和再次发送；发送失败保留草稿供重试。草稿操作不撤销已同步的日程，也不创建候选日程。
5. 失败日志显示出错步骤与错误摘要；再同步成功后，同一封邮件仍是一条 trace，各次尝试分别保留。失败请求已经返回的 Token 和费用也计入这封邮件的累计值。重复同步已处理邮件不再创建尝试、不再计费。「待匹配原日程」表示仍未处理成功；上下文未变时，自动同步不新增模型调用或日志尝试。补充或修正原日程后会恢复自动重试，也可点击「同步真实邮箱」手动重试。

日志只保存短快照：邮箱地址、手机号、已配置密钥、常见密钥格式和链接中的凭据/查询参数会脱敏；长文本和长数组会截断。邮件 ID 使用摘要关联，原文仍在原有邮件详情中查看。历史邮件在本功能上线前没有执行日志，页面会提示缺少记录；不会补造工具调用、耗时或 Token，也不会为了补日志重新处理邮件。

示例使用同一日志面板演示流程，明确标注「预置结果」，模型 Token/成本为零。示例不会进入真实邮件平均费用。

### 配置费用统计

在「邮箱与模型设置」填写输入、输出和缓存输入的 **人民币单价（元 / 百万 Token）**，数值以所用模型服务商的计价页面为准。单价允许为 0；留空表示尚未配置。按实际返回的缓存命中数量分开计算：

```text
估算费用（元） = ((输入 Token − 缓存命中 Token) × 输入单价
               + 缓存命中 Token × 缓存输入单价
               + 输出 Token × 输出单价) / 1,000,000
单封平均（分） = 真实邮件累计费用 / 真实邮件数 × 100
```

一封邮件重试多次的成本会累加，邮件数仍只算一封。模型用量支持 Chat Completions 的 `usage.prompt_tokens` / `completion_tokens`，缓存命中支持 `prompt_tokens_details.cached_tokens` 或 `prompt_cache_hit_tokens`。模型费用是按本次保存单价计算的估算，不是服务商账单；修改单价不追溯改写已有调用。

如果接口没返回 usage，或有计费 Token 对应的单价未填，费用显示「未知」。汇总同时展示已知费用及覆盖数量；完整平均费用只有全部真实邮件费用已知时显示，已知样本的平均值单独标注。不会把未知费用当作零。无需缓存输入价格的请求（缓存命中为 0）只要求输入和输出价格。

## 4. 接入多个邮箱

### 开启邮箱的 IMAP/SMTP 客户端服务

在邮箱服务商的设置中启用 IMAP/SMTP，取得第三方客户端使用的授权码、应用专用密码或被允许的客户端密码。QQ 默认选项继续可用，可在 [QQ 邮箱](https://mail.qq.com/) 设置中开启服务并生成授权码；163、126、Gmail、Outlook 和 iCloud 按各自账号的服务要求设置。

当前使用邮箱地址 + 客户端凭据登录标准 IMAP/SMTP，不提供 OAuth 登录。服务商或组织若只允许 OAuth，不能仅凭服务器预设完成连接；需要使用允许这种客户端登录方式的邮箱。

### 在 Daylight 新增、设置和切换邮箱

1. 打开「邮箱与模型设置」，选择已有邮箱进行编辑，或点击新增邮箱。
2. 选择邮箱服务，填写地址、客户端授权码/密码以及每次读取数量。首次联调建议先设为 3–5 封。
3. 预设会填写服务器；企业邮箱或其他邮箱选择「自定义」，在服务器设置中填写 IMAP、SMTP 主机、端口和连接方式。
4. 保存新邮箱后，页面切换到它自己的日历、待办和邮件记录。邮箱和共用模型配置完整时，新增/切换会立即在后台同步最近 N 封；处理期间可查看日志。
5. 使用侧栏的当前邮箱选择框切换，或在设置中选择已保存邮箱。切回旧邮箱会恢复它原有的日程、待办完成状态、草稿和日志，同时重新读取该邮箱最近 N 封；已经成功处理或跳过的邮件不会再次调用模型，失败邮件可以重试。

| 邮箱服务 | IMAP | SMTP |
| --- | --- | --- |
| QQ 邮箱（默认） | `imap.qq.com:993`，直接 TLS | `smtp.qq.com:465`，直接 TLS |
| 163 邮箱 | `imap.163.com:993`，直接 TLS | `smtp.163.com:465`，直接 TLS |
| 126 邮箱 | `imap.126.com:993`，直接 TLS | `smtp.126.com:465`，直接 TLS |
| Gmail | `imap.gmail.com:993`，直接 TLS | `smtp.gmail.com:465`，直接 TLS |
| Outlook | `outlook.office365.com:993`，直接 TLS | `smtp-mail.outlook.com:587`，STARTTLS |
| iCloud | `imap.mail.me.com:993`，直接 TLS | `smtp.mail.me.com:587`，STARTTLS |
| 自定义 IMAP/SMTP | 手动填写 | 手动填写 |

每个邮箱分别保存邮箱服务、地址、客户端凭据、服务器和读取数量（1–50 封，默认 15 封）。收信和发信共用该邮箱的客户端凭据。直接 TLS 选项关闭时使用 STARTTLS，仍要求加密连接。SMTP 使用操作系统 DNS 解析主机，并按配置的 SMTP 域名验证 TLS 证书，不固定 IP。读取范围是 `INBOX` 最近 N 封，包含已读和未读邮件。

日程、待办、邮件、冲突、草稿、日志和费用按邮箱独立保存，取消/调整匹配和任务去重仅查看当前邮箱。模型 URL、API Key、模型名称及 Token 单价共用。换成新的邮箱地址会创建或切换到独立邮箱，不继承其他地址的授权码或日历。同步或发信期间暂停邮箱切换，完成后再切换。

服务每分钟只自动同步当前邮箱；也可以点击日历或邮件助手的「同步真实邮箱」。**保存配置或显示“已配置”只表示字段已保存，不表示连接成功。** 首次填写原默认邮箱后，可立即手动同步或等待下个自动周期；发信连接发生在点击「采纳并发送」时。发送已有草稿不需要模型配置。编辑同一邮箱时，凭据留空保留该邮箱已保存的值；新增地址需要自己的凭据。

### 采纳草稿并发送真实回信

更新代码后，重启正在运行的本地 Node 服务（开发模式重新执行 `npm run dev`），再刷新页面使用发送入口。

1. 打开一封已同步的真实邮件，在处理日志中查看回复草稿。旧版本已点击「采纳草稿」的记录也可发送：此前的采纳只记录了反馈，尚未发信。
2. 核对草稿；需要修改时点击编辑，先保存修改稿。编辑器展示准备发送的正文，普通联系方式和链接查询参数按原文保留；发送时优先使用已保存的修改稿，没有修改稿则使用原稿。旧版本的修改稿若已被脱敏，无法恢复其中的内容，可重新编辑补全后发送。
3. 点击「采纳并发送」，服务使用当前邮箱的 SMTP 配置回信给原邮件 `Reply-To` 中的第一个有效邮箱地址；没有有效 `Reply-To` 地址时回复发件人。页面提示仅回复这个地址，不执行「回复全部」。主题使用 `Re:`，新读取邮件保留原邮件的 `Message-ID` 和 `References`，用于设置回复关联；历史邮件没有这些头信息时仍可按已保存的发件人地址回信。其他邮箱的草稿在当前空间不可见，也不能在此发送。
4. 成功后查看发送时间，刷新仍保留发送状态，编辑和发送按钮禁用。相同草稿的成功记录不会再次发送。失败会显示错误并保留草稿；检查 IMAP/SMTP 服务和授权码后可再次点击重试。
5. 在发件人的邮箱确认收到回信。页面「已发送」表示配置的 SMTP 服务已接受邮件，不等于收件人最终收到或已读。本 demo 没有额外向「已发送」文件夹归档的操作。

拒绝草稿不会发信；预置示例仍只保存采纳、修改或拒绝反馈。自动同步不会自动发信，发送回信也不会把冲突候选时段加入日历。

### 每分钟自动同步

- 启动 `npm run dev` 或 `npm start` 后，Node 服务每 60 秒检查当前邮箱和共用模型配置；配置完整时同步当前邮箱，其他邮箱在切换后同步。
- 自动同步先获取最近 N 封的 UID 和日期，按当前邮箱的邮件 ID 去重；成功、跳过或已有冲突草稿的邮件不重复下载原文，也不调用模型。未处理邮件读取原文后按时间顺序解析，日程和待办直接导入，冲突日程同时标识并生成待确认回复草稿。
- 日程取消/调整因目标缺失、不唯一或无效而失败时，若当前有效日程、已有任务和模型接口/名称/提取规则版本未变，自动同步及邮箱切换同步会暂缓该邮件的模型重试。错误仍保留，不标为成功；补充或修正日程、改变任务或模型上下文后会恢复，手动同步也可立即重试。暂缓的失败邮件仍会读取原文。网络、服务商、响应格式和其他处理错误继续在后续周期重试，均受最近 N 封范围限制。
- 自动同步和手动同步共用一次处理流程；已有同步正在运行时，本轮自动同步跳过，避免同时处理。页面会定期刷新状态，自动同步有新处理结果或新失败时显示提示；仅有已暂缓的匹配错误时不反复弹出提示。
- 关闭页面后，只要 Node 服务仍运行，自动同步继续；停止服务后自动同步也停止。这里使用每分钟轮询，不是收件推送。

## 5. 配置真实模型 API

本项目使用 **OpenAI 兼容 Chat Completions 接口**。所选模型需支持 `messages`、`system` 提示词，以及 `response_format: { "type": "json_object" }`。

在同一个设置窗口填写：

| 页面字段 | 填写内容 |
| --- | --- |
| Base URL | 模型服务商给出的兼容接口基础地址 |
| API Key | 该服务商的 API 密钥 |
| 模型名称 | 该服务商提供的准确模型 ID，且你的账户有调用权限 |

本机已成功使用的 DeepSeek 配置如下（不含 API Key）：

```text
Base URL: https://api.deepseek.com
模型名称: deepseek-flash
实际请求: POST https://api.deepseek.com/chat/completions
```

这组配置已由用户通过真实邮件联调确认。程序初始默认的 `https://api.deepseek.com/v1` / `deepseek-chat` 是另一组填写示例，当前本机已改用上述配置。

连接官方 `api.deepseek.com` 且模型为 `deepseek-flash` 或 `deepseek-v4-pro` 时，提取请求明确关闭思考模式，减少本任务不需要的推理等待。其他模型或兼容服务按通用 Chat Completions 格式请求。每次模型请求设 **60 秒等待上限**，覆盖请求与响应正文读取；超时后保留失败记录，其他邮件继续处理。该上限针对单次模型调用，整批同步仍包含邮箱连接、邮件读取及各封模型请求的耗时。

其他填写示例如下；具体模型可用性和权限以服务商控制台为准。通义千问、OpenAI 及表中其他模型组合尚未在本项目中实连验证。

| 服务商 | Base URL | 模型名称示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| OpenAI | `https://api.openai.com/v1` | 账户可用、支持 Chat Completions 和 JSON object 输出的模型 ID |

例如选择 DeepSeek，可填写第一行的 URL、你的 DeepSeek API Key 和 `deepseek-chat`，再点击「保存配置」。初始 URL 和模型名称只是默认值，仍需要填写真实 Key。

后端会在 Base URL 后追加 `/chat/completions`；如果填写的地址已经以 `/chat/completions` 结尾，会直接使用该地址。例如：

```text
Base URL: https://api.deepseek.com/v1
实际请求: POST https://api.deepseek.com/v1/chat/completions
鉴权: Authorization: Bearer <你保存的 API Key>
```

请求包含邮件日期、当前北京时间、主题、发件人、正文，以及当前邮箱有效的非示例日程和已有非示例任务摘要，用于匹配取消/调整对象和重复任务。其他邮箱的日程、任务和邮件不会进入这次模型请求。模型在同次请求中返回 `summary`、`category`、`priority`、`events`、`tasks`。共用模型配置保存在 `data/settings.json`；无需创建 `.env`。

### 真实流程复验或首次配置新环境

当前本机已完成真实联调。更换环境、模型或验证新功能时，可以按以下步骤复验：

1. 保存邮箱地址、授权码、Base URL、API Key 和模型名称，将读取数量设为 3–5 封。
2. 向当前邮箱发送一封新的测试邮件，写清具体日期、时间和地点，例如：

   ```text
   主题：Daylight 日程提取测试
   正文：邀请你参加产品评审，时间为 2026 年 10 月 20 日 14:00–15:00，
   北京时间，地点为腾讯会议 123 456 789。请带上最新设计稿。
   ```

   将示例日期改为你准备测试的日期，并确保测试邮件位于收件箱最近 N 封范围内。

3. 等待下一个每分钟自动同步周期，或点击日历/邮件助手「同步真实邮箱」。有明确的安排会自动生成日程，有冲突也会入历并标识，可查看冲突详情和待确认回复草稿。
4. 查看日历中的日程和邮件助手中的来源记录；核对时间、地点和标题。
5. 再次同步，同一封已处理邮件应跳过。

### 真实邮件演示取消与调整

先把读取数量设为能覆盖测试邮件的范围，例如最近 10 封。建议用同一发件人，保留独特活动名及原时间地点；可以回复原邀请发送通知。以下均为专门编写的测试文案，时间为北京时间，按演示当天修改日期。

**取消流程：**

1. 发送主题「Daylight 演示 A：产品评审邀请」，正文「邀请你参加 Daylight 演示 A 产品评审，2026 年 10 月 20 日 14:00–15:00，地点会议室 A。」
2. 点击「同步真实邮箱」，确认邀请已生成日程。
3. 再发送主题「取消：Daylight 演示 A 产品评审」，正文「原定 2026 年 10 月 20 日 14:00–15:00 在会议室 A 的 Daylight 演示 A 产品评审取消。原因：负责人临时出差，无需参加。」
4. 再次同步，确认原日程有「已取消」提示；在详情里查看原因及变更邮件。

**调整流程：**

1. 发送主题「Daylight 演示 B：设计沟通邀请」，正文「邀请你参加 Daylight 演示 B 设计沟通，2026 年 10 月 21 日 10:00–11:00，地点会议室 B。请携带设计稿。」同步确认日程已生成。
2. 再发送主题「调整：Daylight 演示 B 设计沟通」，正文「原定 2026 年 10 月 21 日 10:00–11:00 在会议室 B 的 Daylight 演示 B 设计沟通调整为 2026 年 10 月 22 日 15:00–16:00，地点改为会议室 C。原时间的安排取消，其他事项不变，请以最新通知为准。」
3. 同步后确认原时间保留「已调整」记录，10 月 22 日新建有效日程，时间和地点正确；打开原/新日程互相跳转。
4. 重复同步确认没有重复新增、取消或调整。也可在调整后再发送新的取消通知，明确指向调整后的时间地点，验证最新安排取消。

同一批同时包含邀请和变更时，会按邮件时间从早到晚处理。模型从当前有效的真实/手动日程中选择唯一目标，按正常取消或调整流程更新。当前提取规则还包括：

- 通知对应的活动已能唯一确认，且时间、地点及其他变更都与日历中的最新安排一致时，不重复调整或创建，保留说明摘要。
- 没有任何相关原安排或最新安排，但调整通知给出了明确日期及完整可参加的新活动时，可按通知直接创建最新安排，并在备注说明来源。
- 没有相关日程的纯取消通知保留摘要，不修改其他安排。
- 有疑似目标但不能唯一匹配，或调整内容不足以形成完整安排时仍显示失败，不猜目标、不部分写入。上下文未变时暂缓自动模型重试，手动同步可以重试；返回无效目标或无效时间也会失败。暂无人工选择候选界面，可补建或修正原日程，或发送说明更明确的新通知。

此前多邮箱与冲突入历使用合成数据验证；本次同步优化另有真实 IMAP 和官方 DeepSeek 复验，见 `STATUS.md`。上述步骤用于逐项复验新功能，内置预置演示不代表真实模型识别结果。

### 真实邮件复验冲突

1. 先选一个测试日期，手动新建「冲突测试·已有安排」，例如 2026 年 10 月 23 日 14:00–15:00。
2. 发一封新的测试邮件到当前邮箱：主题「冲突测试·讨论邀请」，正文「邀请你参加冲突测试讨论，2026 年 10 月 23 日 14:30–15:30，地点会议室 C。如果时间不方便，请提供其他时段。」按演示当天修改日期，并确保邮件位于最近 N 封范围内。
3. 手动同步或等待自动同步。核对原日程保留、新邀请已加入，两个安排显示冲突；打开冲突卡片核对标题和时间，查看含 3 个可行时段的待确认回复草稿。改期冲突同样入历，原安排标记已调整。
4. 核对回复内容，可修改后保存，再点击「采纳并发送」；在测试发件人邮箱确认收到回信。刷新后应保留发送时间，无法再次发送；拒绝则只保存反馈。再次同步应跳过原邮件，发送回信不会创建建议日程。
5. 另发一封日期/时间与有效日程完全错开的新邀请，确认它可以正常自动创建。

冲突判断和候选生成在本地执行，复用模型提取的时间字段，不增加模型调用。多邮箱切换、冲突入历与草稿发送已有本地合成数据验证；新流程及其他邮箱仍需真实服务复验，历史 QQ SMTP 连接和完整回信送达记录见 `STATUS.md`。

### 当前错误提示怎么处理

- **邮箱登录失败**：检查邮箱地址、IMAP 是否开启，以及授权码是否有效。
- **回信发送失败**：检查当前邮箱 SMTP 服务是否开启、服务器/端口/连接方式、邮箱地址和客户端凭据是否正确，以及网络连接；草稿保留，可检查后重试。
- **DNS lookup for smtp.qq.com timed out**：本次已改为使用系统 DNS，修复本机 Nodemailer 直接 DNS 查询超时的问题；重启 Node 服务后再发送。如果系统 DNS 本身也无法解析，检查本机网络或代理的 DNS 设置。
- **模型提示 Key、权限或额度错误**：检查 API Key、模型名称及服务商账户状态。
- **模型返回格式或日期错误**：确认模型支持上述 Chat Completions 和 JSON object 请求格式；当前代码会提示格式错误。
- **模型请求超过 60 秒**：本次已停止等待并保留失败；检查服务商状态和网络后可再次同步，后续自动周期也会重试。
- **取消/调整匹配失败或待匹配原日程**：核对原日程是否存在且有效，通知中补充独特活动名和原时间地点；手动日程可被真实邮件匹配，示例日程不会被真实邮件改变。匹配上下文未变时自动同步暂缓重复模型请求；补充/修正原日程后会恢复，也可手动点击「同步真实邮箱」重试。
- **显示日程冲突**：冲突安排已写入并标识；打开冲突卡片核对安排和 3 个建议时段，再采纳、修改或拒绝回复草稿。建议时段不会自动替换日历，新的明确改期通知可更新日历。此前版本暂缓的历史记录仍保留原样。
- **没有日程变更**：查看该邮件是否已处理、是否有冲突提示、是否包含明确安排，或是否已超出最近 N 封读取范围。

单封提取失败不会阻止其他邮件继续处理。失败邮件不写入已处理记录，仍处于读取范围内时可手动重试；目标匹配失败按上面的上下文规则恢复自动重试，其他故障在后续自动周期继续重试。

已成功处理、跳过或保存冲突草稿的邮件会被记住。更换模型或删除对应日程后，同一封邮件也不会重新提取；再次联调可发送一封新的测试邮件。

## 6. 本地数据和当前边界

- `data/calendar.json`：日程、待办及完成状态、已处理邮件正文与标签、来源关联、邮件结构化提取快照、冲突对象与候选时段、邮件 `draftReply` 原始草稿及 `userDraft` 修改稿原文、最近同步时间。页面编辑器和真实发送使用这里保存的完整正文。
- `data/settings.json`：邮箱列表、当前邮箱 ID、各邮箱地址、客户端凭据、IMAP/SMTP 服务器及读取数量，以及共用模型 API Key、URL、模型名称和单价。
- `data/traces.json`：脱敏处理日志、阶段快照、工具调用摘要、用量与计价快照、累计费用、各次重试、脱敏草稿证据、用户反馈及 `reply_delivery` 发送状态（成功时间/邮件 ID 或失败时间/脱敏错误）。日志草稿证据与准备发送的正文分别保存。
- 原默认邮箱继续使用 `data/calendar.json` 和 `data/traces.json`；新增邮箱分别使用 `data/mailboxes/<邮箱 ID>/calendar.json` 和 `traces.json`。首次读取旧设置时兼容原邮箱，已有数据不会被清空或搬走；新增邮箱从空日历和待办开始，示例可在该空间单独导入或清除。

上述 JSON 文件以明文保存在本机；页面 API 不回传已保存的密钥值。真实同步时，未处理邮件、当前有效日程和已有任务摘要会发送到你配置的模型服务商。`data/` 已加入 `.gitignore`，分享源码时请排除该目录。

当前服务每分钟自动同步，也支持手动点击同步，识别正文中的新邀请、取消和时间/地点等调整。自动同步只在本地 Node 服务运行且邮箱、模型配置完整时执行，读取范围仍是最近 N 封。原取消日程保留用于展示和追溯；调整后的日程独立保存，未提及的字段继承原安排。旧数据没有 `status` 字段时作为有效安排处理，无需迁移或重新配置。

每次同步仍需连接 IMAP、打开 INBOX 和检查元数据；首次全新邮件仍需读取原文并按时间逐封调用模型。未处理邮件仍下载整封源数据，包括附件字节，新 PDF 附件会进行简历识别，扫描页执行本地 OCR；其他类型附件暂不解析。暂停模型重试的匹配失败邮件也仍读取原文；免下载原文适用于已成功处理、跳过或保存冲突草稿的邮件，不保证所有同步零下载或固定耗时。

目标匹配依赖配置的模型；名称相近、通知信息不完整时，识别效果需要真实邮件验证。待办支持在当前邮箱内跨邮件合并；普通新邀请按不同邮件分析，不做活动层面的自动合并。非全天邀请重叠也加入日历，保留冲突标识和回复流程，全天活动正常加入且不占时段。已取消活动重新邀请应作为新日程。待办来源链接指向本地保存的邮件详情。真实回信使用当前邮箱的已保存草稿与 SMTP 配置；PDF 简历与本地 OCR 已支持；非简历附件不解析为业务事项。OAuth、提醒、实时收件监听和第三方日历同步尚未实现。其他邮箱服务的实际可用性仍需按账号权限实连验证。

模型提示词要求明确日期、相对日期参考邮件日期、缺少结束时间默认一小时、日期事项生成全天日程。真实测试邮件已成功生成日程；复杂日期、多日程及其他邮件格式的提取效果仍需按后续需求验证。
